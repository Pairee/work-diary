# 업무일지 (work-diary)

AI 코딩 앱에서 한 일을, 개발을 모르는 사람도 읽을 수 있는 **업무일지**로 하루 세 번 저절로 쌓아 주는 스킬입니다.
클로드 코드 · 코덱스 · 안티그래비티 · 제미나이 CLI에서 똑같이 쓰고, 맥과 윈도우를 모두 지원합니다.

![업무일지가 만들어지는 흐름](skills/work-diary/assets/work-diary-flow.png)

## 설치 (명령어 한 줄)

**맥** · 터미널에 붙여 넣기

```bash
curl -fsSL https://raw.githubusercontent.com/Pairee/work-diary/main/install.sh | bash
```

**윈도우** · PowerShell에 붙여 넣기 (파이썬과 git을 먼저 설치하세요)

```powershell
irm https://raw.githubusercontent.com/Pairee/work-diary/main/get.ps1 | iex
```

설치 파일이 이 컴퓨터에 있는 AI 앱을 찾아, 앱마다 정해진 스킬 폴더에 넣습니다. 프로젝트 폴더에는 아무것도 넣지 않습니다.
명령어가 어려우면 [Releases](../../releases)에서 맥·윈도우용 zip을 받아 **설치하기**(맥) / **install.bat**(윈도우)을 더블클릭하세요.
설치가 끝나면 **열려 있던 AI 앱을 완전히 껐다가 다시 켜세요.**

## 켜기

기록할 프로젝트 폴더에서 AI 앱을 열고 이렇게 말합니다.

> 이 폴더 업무일지 켜줘

하루 세 번(11:30 · 15:30 · 18:30) 그 폴더에서 바뀐 것을 읽어 `~/worklog/<프로젝트이름>/YYYY-MM.md`에 이어 붙입니다.
처음 켤 때 앱이 예약 실행 등록을 물으면 허용하세요.

| 하고 싶은 것 | 앱에 이렇게 말한다 |
| --- | --- |
| 지금 한 편 쓰기 | 오늘 한 일 정리해줘 |
| 지난 날 채우기 | 9월 1일부터 쭉 기록해줘 |
| 잘 되는지 보기 | 업무일지 기록 잘 되고 있어? |
| 끄기 (일지는 남음) | 업무일지 기록 멈춰 |

### 짧은 명령

말 대신 스킬 이름 뒤에 한 단어를 붙여 불러도 됩니다.

| 앱 | 부르는 법 |
| --- | --- |
| 클로드 코드 | `/work-diary 켜기` (플러그인으로 설치했다면 `/work-diary:work-diary 켜기`) |
| 안티그래비티 | `/work-diary 켜기` |
| 코덱스 | `$work-diary 켜기` (코덱스는 `/` 가 아니라 `$`) |

| 붙이는 말 | 하는 일 |
| --- | --- |
| `켜기` | 지금 폴더 등록 + 자동 기록 시작 + 첫 한 편 보여 주기 |
| `지금` | 지금 한 편 쓰기 |
| `채우기 2026-09-01` | 그날부터 어제까지 하루씩 채우고 요약 |
| `요약` | 이번 달 요약 다시 쓰기 |
| `상태` | 판 번호·등록된 프로젝트·자동 기록 시각·최근 기록 보기 |
| `시간 09:30,14:00,18:00` | 자동 기록 시각 바꾸기 |
| `끄기` | 이 프로젝트 기록 멈추기 (일지는 남음) |
| `업데이트` | 새 판이 있는지 확인 |

## 한 편은 이렇게 생겼습니다

```markdown
## 2026-09-18 (금) 15:30 · 오후 기록

**한 줄 요약**: 신청서에 엑셀 파일을 첨부할 수 있게 됐고, 올릴 수 없는 파일은 그 이유를 바로 안내합니다.

**무엇을 했나**
- 신청서 화면에서 엑셀 파일을 첨부해 제출할 수 있게 했습니다.
- 10MB가 넘거나 엑셀이 아닌 파일은 올라가지 않도록 막았습니다.

**어떻게 했나**
- 파일을 받는 자리에서 크기와 형식을 먼저 확인하도록 고쳤습니다.

**왜 했나**
- 지난주 20MB 이미지가 올라가 서버가 5분 멈춘 일이 있었고, 재발을 막기 위해서입니다.

<sub>근거: 커밋 3건(9c61b7e, 58bbe83, a33afdb)</sub>
```

지키는 것 세 가지: 파일 이름은 맨 아래 근거 줄에만 · 확인 안 된 이유는 지어내지 않기 · 쓸 게 없으면 안 쓰기.

## 새 판 알림과 업데이트

스킬은 하루 한 번 이 저장소의 최신 판 번호를 봅니다. 새 판이 있으면 `상태`를 볼 때나 스킬을 쓸 때 끝에 알림이 붙습니다.
**알리기만 하고 스스로 바꾸지는 않습니다.** 업데이트는 받은 방법대로 한 번 더 받으면 됩니다.

| 받은 방법 | 업데이트 |
| --- | --- |
| 한 줄 설치 (맥·윈도우) | 설치 명령을 한 번 더 실행 |
| zip 더블클릭 | 새 zip을 받아 다시 더블클릭 |
| 클로드 코드 플러그인 | `claude plugin update work-diary@work-diary` 후 앱 재시작 |
| `npx skills` | `npx skills update` |

앱에 `/work-diary 업데이트`라고 하면 확인해 주고, 동의하면 앱이 설치 명령을 대신 실행합니다.

## `/work-diary` 가 안 보일 때

1. **앱을 완전히 껐다가 다시 켜세요.** 새로 설치한 스킬은 앱을 다시 켜야 보일 수 있습니다.
2. **코덱스는 `$work-diary`** 입니다. `/` 목록에는 나오지 않습니다.
3. **클로드 코드에서 쓰세요.** 클로드 데스크톱 앱의 일반 대화와 claude.ai 웹은 이 스킬 폴더를 읽지 않습니다.
   클로드 코드(터미널, 또는 데스크톱 앱의 Code 화면)에서 보입니다.
4. **설치 결과를 보세요.** 설치할 때 `넣음: 클로드 코드` 대신 `건너뜀: 클로드 코드`가 나왔다면 그때 클로드 코드를 찾지 못한 것입니다.
   클로드 코드를 설치한 뒤 설치 명령을 다시 실행하세요.
5. 그래도 안 보이면 말로 부르세요. "이 폴더 업무일지 켜줘"도 같은 일을 합니다.

## 보안과 개인정보

**일지는 사용자 개인 컴퓨터에만 쌓이는 구조입니다.** 서버도, 관리자도, 만든 사람도 없습니다.
이 스킬은 어떤 기록도 모으거나 보내지 않습니다.

| 무엇 | 어디에 | 누가 보나 |
| --- | --- | --- |
| 업무일지 | 내 컴퓨터 `~/worklog/<프로젝트이름>/` | 나 (파일을 열어 보거나 직접 공유할 때만) |
| 등록 목록 · 설정 · 실행 기록 | 내 컴퓨터 `~/.work-diary/` (본인만 읽기) | 나 |
| 업무일지 폴더 권한 | `~/worklog` 도 본인만 읽기 | 같은 PC 의 다른 계정은 못 읽음 |
| 일지를 쓰기 위한 재료 (커밋 메시지 · 바뀐 파일 목록 · 변경 내용 일부) | 켤 때 고른 AI 앱 | 평소 그 앱으로 코딩할 때와 같은 곳 |
| 새 판 확인 | 이 저장소의 `VERSION` 파일을 하루 한 번 읽음 | 내용은 보내지 않음. 접속 기록(IP)은 깃허브에 남음 (끌 수 있음) |

**AI 앱으로 가는 것을 줄이기 위해**
- `.env` · 키 파일 · 인증서 같은 비밀 파일은 변경 내용에서 뺍니다.
- 코드 안에 직접 적힌 토큰 · API 키 · 비밀번호 · 개인 키 모양의 값은 보내기 전에 `[가림]`으로 바꿉니다.
  그래도 비밀값은 코드에 두지 않는 것이 가장 안전합니다.
- 다른 사람의 커밋은 읽지 않습니다. 저장소에 설정된 **내 메일과 정확히 일치하는** 커밋만 보고(메일이 없으면 이름),
  설정이 없으면 커밋을 읽지 않고 멈춥니다. 커밋 본문의 `Co-Authored-By` 같은 동료 이름·메일 줄은 뺍니다.
- 새로 만든 파일의 앞부분은 코드·문서 확장자일 때만 보여 주고, 키·인증서·설정 파일은 이름만 남깁니다.
  심볼릭 링크는 열지 않습니다. 메일 주소·휴대전화·주민번호 모양은 `[가림]` 처리합니다.

**AI는 글만 씁니다.** 자료는 전부 표준입력으로 넘기고, AI 는 **빈 임시 폴더**에서 실행됩니다. 프로젝트 폴더를 열어 볼 수 없고
프로젝트 안의 설정도 실리지 않습니다. 클로드는 도구를 전부 끈 채로, 코덱스는 읽기 전용 샌드박스로, 제미나이는 계획 모드로 부릅니다.

**남이 쓴 글은 자료로만 다룹니다.** 커밋 메시지·파일 내용에 "이전 지시를 무시하라" 같은 문장이 있어도 AI 에게는
자료라고 못 박아 넘기고, 정해진 칸 형식이 아닌 응답은 버립니다. 그래도 AI 가 자료 속 문장을 그대로 인용할 수는 있으니
일지를 읽을 때 낯선 지시문이 보이면 따르지 마세요.

**권한.** 예약 실행은 맥 사용자 launchd, 윈도우 사용자 작업 스케줄러에 등록되며 관리자 권한을 쓰지 않습니다.
설치는 앱마다 정해진 스킬 폴더에만 파일을 넣고, 프로젝트 폴더는 건드리지 않습니다.

**한 줄 설치에 대해.** `curl | bash` · `irm | iex`는 인터넷의 파일을 바로 실행하는 방식입니다.
받기 전에 [install.sh](install.sh) · [install.ps1](install.ps1)을 열어 보셔도 되고, 대신 Releases의 zip을 받아 더블클릭해도 됩니다.

**회사 안에서 쓸 때.** 일지는 회사 코드에서 한 일을 읽기 쉬운 말로 옮긴 것이라 **그 자체가 사내 자료**입니다.
밖으로 보낼 때는 회사의 자료 반출 규정을 따르고, 회사 챗봇이 아닌 외부 AI 에 코드나 대화를 넣을 때는 회사의
AI 이용 규정을 먼저 확인하세요. 스킬 자체는 아무것도 밖으로 보내지 않습니다.

## 다른 설치 방법

스킬 도구로 받아도 됩니다. 켜는 방법은 같습니다.

| 도구 | 명령 |
| --- | --- |
| 여러 앱 공용 | `npx skills add Pairee/work-diary` (node 22 이상 권장) |
| 클로드 코드 플러그인 | `/plugin marketplace add Pairee/work-diary` → `/plugin install work-diary@work-diary` |
| 제미나이 CLI | `gemini skills install https://github.com/Pairee/work-diary --path skills/work-diary` |
| 코덱스 | 앱에서 `$skill-installer https://github.com/Pairee/work-diary/tree/main/skills/work-diary 설치해줘` |

## 챗봇만 쓴다면

a.biz · ChatGPT · Gemini 웹처럼 스킬을 설치할 수 없는 곳에서는
[`skills/work-diary/references/chatbot-prompt.md`](skills/work-diary/references/chatbot-prompt.md)의 프롬프트를
하루를 마칠 때 붙여 넣으면 같은 모양의 일지가 나옵니다.

## 지우기

- 맥: `curl -fsSL https://raw.githubusercontent.com/Pairee/work-diary/main/install.sh | bash -s -- --uninstall`
- 윈도우: 내려받은 폴더에서 `install.bat -Uninstall`

쌓인 일지(`~/worklog`)와 기록 상태(`~/.work-diary`)는 지우지 않습니다.

## 필요한 것

- 맥 또는 윈도우, 파이썬 3.8 이상, git
- 클로드 코드 · 코덱스 · 안티그래비티 · 제미나이 CLI 중 하나 이상 (로그인된 상태)
